# Сессия 2026-09-21 … 2026-09-25 — что изменили и зачем

Журнал одного длинного диалога с агентом. Для каждой темы: **цель** (чего добивались), **что сделано**, **где**.
Текущее состояние проекта — [../../PROJECT_STATE.md](../../PROJECT_STATE.md). Проверки по замечаниям пользователя — [../../guidelines/USER_CORRECTED_CHECKLIST.md](../../guidelines/USER_CORRECTED_CHECKLIST.md).

Общая цель всех правок: довести `:app-compose` (phone + TV в одном APK) до состояния, когда он **заменяет legacy `:app` в Google Play**. Phone должен совпадать с legacy, TV — удобно управляться пультом.

- В `data/build.gradle.kts` захардкоженный `room-compiler:2.8.0` заменён на `libs.androidx.room.compiler`.

## 2. Edge-to-edge Android 15/16

**Цель:** на targetSdk 35+ контент не должен уходить под status/navigation bar.

- **Legacy `:app`** (по skill `android-prepublish-refresh` §3): `enableEdgeToEdge` + `fitsSystemWindows` на root для Search / Splash / Privacy / Onboarding. У sticky banner/CTA убран нижний margin (двойной зазор), `fitsSystemWindows` снят с `NavigationView` и `fragment_terms`.

## 3. TV shell: навигация и фокус

**Цель:** TV — это адаптация phone-UI под D-pad, а не отдельное приложение. Всё, что есть на phone, доступно с пульта. Используется только `androidx.tv.material3`.

| Что | Зачем |
|-----|-------|
| `NavigationDrawer` в TV `MainShell`, `LazyColumn`, полный набор пунктов phone-drawer + Search/Tutorial из top bar + FAB «Add playlist» | На TV не терять функции phone; при многих пунктах drawer должен скроллиться |
| `TvFocusTabRow` (Playlist / Channel / Category / Favorites со счётчиками), `onFocus` сразу меняет контент | Как Cinema `HomeTvScreen`: переключение без OK |
| Tint иконок drawer `onSurface` | Чёрные иконки не видны на тёмном rail |
| `TvTheme` = тема Cinema (JetStream dark / LightColorsTv) | Единый TV-стиль по референсу |
| `tv/MainActivity`: в DEBUG принудительный landscape | Отладка TV-UI на телефоне |
| `focusRestorer(drawerFallback)` у drawer, `left = drawerGroupFocus` у контента | Left возвращает в тот пункт drawer, откуда ушли; ручной save/restore ломается на Lazy |
| Search, Playlist Management, Settings, Tutorial & FAQ открываются внутри shell | Drawer остаётся, Left с первой колонки → меню |
| `TvEditableField`: фокус = редактирование, Up/Down уходят, Back снимает фокус, Left в начале строки → drawer | Поле ввода не должно захватывать D-pad |
| About и choice-диалоги Settings — Compose `Dialog` | Фокус на OK, нижний слой не слушает D-pad, Back/Left/Right закрывают |
| Tutorial — `LazyColumn` из focusable-блоков | Up не должен прыгать сразу на таб |
| `NotificationManager` + `NotificationOverlay` (иконки `CheckCircle` / `Error`) | Результат Subscribe/Refresh — toast без захвата фокуса, как LDS NotificationManager |
| `TvLoadingOverlay` («LOADING») | Как legacy loading dialog на время парсинга |
| Карточка плейлиста: клик → открыть, long-press → диалог Refresh / Delete / Cancel; действие на **KeyUp**, arm ~300 мс, фокус на Cancel | Кнопки внутри Card на TV не работают; отпускание OK не должно нажимать кнопку диалога |
| Сетка каналов на TV — 4 колонки; при 1 колонке — list-row как legacy `item_channel_list` (превью, название, категория, описание, geo, избранное) | Одна колонка с `aspectRatio(1f)` раздувалась на весь экран |
| Заливка-placeholder только под логотипом канала | Прозрачные PNG выглядели «дырявыми» |
| Иконка источника (`cloud/local/buffer/xtream`) на `PlaylistCardTv` | Потеряна при порте, на phone была |

Все пункты закреплены в skill `~/.cursor/skills/compose-tv-from-mobile` и в `USER_CORRECTED_CHECKLIST.md`.

## 4. TV-плеер

**Цель:** плеер на TV полностью управляется пультом, при этом используется тот же JZ-движок, что на phone.

- Свой `ui/tv/player/PlayerScreenBody`: immersive, без phone Scaffold / Cast / BottomSheet.
- Compose-chrome поверх JZ: избранное + Close сверху, Play/Pause/Replay по центру (иконки Cinema, 64dp), Canvas-шкала как `VideoPlayerSeekerTV` (ускоряемый seek Left/Right), Settings снизу. Кнопки фиксированного размера 48dp.
- `resetHideTimer`: любое действие перезапускает 5-секундный таймер скрытия.
- `JZVideoPlayerNew.suppressNativeChrome` — XML-контролы JZ скрыты в release, в DEBUG видны оба слоя (метка `DEBUG: Compose + JZ XML`). Phone не затронут.
- Центральная кнопка повторяет логику XML `@id/start`; на `STATE_ERROR` вызывается `clickRetryBtn()` — иначе «Click to try again» не работал.
- При загрузке фокус не ставится на скрытый Play (Right уходил в пустоту).
- Back сразу выходит из плеера (раньше его глотал обработчик «показать chrome»).
- Fullscreen JZ на TV закомментирован: `gotoFullscreen()` переносит View на DecorView, и Compose-overlay остаётся под ним.
- **Штора каналов** (`PlayerChannelSheet`): Left/Menu открывает, полупрозрачная, каналы по категориям с логотипами; клик переключает канал и **не закрывает** штору; Left/Right/Home/Escape закрывают; Back — сначала штора, потом плеер. CH+/CH− (PageUp/PageDown) — соседние каналы. Отдельная кнопка списка каналов в chrome убрана.
- **Browse scope** (`PlayerBrowseScope`: Favorites / Playlist / Category / None / InferPlaylist), передаётся в Player и Details. Цель: из Favorites штора и CH± показывают избранное, а не весь плейлист. Описание — [../../ARCHITECTURE/player-browse-scope.md](../../ARCHITECTURE/player-browse-scope.md).
- Phone-плеер: prev/next и список каналов в bottom sheet.

## 5. Плейлисты, категории, настройки (phone + TV)

**Цель:** функции legacy на месте, операции над плейлистами не показывают пустой экран.

- **Meta-строка** на карточках (TV, phone, legacy): `N ch · дата добавления · upd дата обновления`; update показывается, только если отличается от import.
- **Subscribe:** `PlaylistManageViewModel` сбрасывал `isSaving` сразу после валидации → overlay не держался. Исправлено. Прогресс добавлен на phone (Dialog) и в legacy (file/clipboard).
- **Playlist link:** кнопка вставки `ContentPaste` на TV под полем, Down программно переводит на неё фокус; на phone — в одном ряду с полем. Иконки у Subscribe / Parse Clipboard / выбора файла.
- **Delete** — подтверждение: TV `TvConfirmDeletePlaylistDialog` (фокус на Cancel), phone `AlertDialog`.
- **Refresh** (общий слой, пользователь отметил, что это надо было согласовать заранее): `PlaylistRefreshResult` (Success / Empty / Failed); при Empty/Failed БД не трогается; при Success перезапись с тем же `_id` через `clearPlaylistChannelLinks`. Цель: список не пропадает («No item»), результат показывается toast'ом.
- **Счётчик каналов на категориях** (`N ch`): `CategoryUi.count` + запрос по `channel.cat` (согласовано с пользователем).
- **Настройка «Empty categories cleanup»** (по умолчанию Off): при включении и при удалении плейлиста удаляет категории без каналов.
- **Settings:** тематические иконки у пунктов (Info, GridView, SortByAlpha, OpenInNew, DarkMode, DeleteSweep, VideoSettings, MenuBook, PrivacyTip).
- **Drawer Search:** использовался `search_hint` («Which channels you want?») вместо короткого лейбла → добавлен `menu_search`.

## 10. Сборка после перехода на AGP 9.1 / Gradle 9.7.1 (25.09)

Пользователь поднял AGP `8.9.3 → 9.1.0` и Gradle `8.14.3 → 9.7.1` (коммит `3d7d045`, «1»). После этого сборка падала.

**Цель:** снова собрать обе debug-APK без миграции модулей на встроенный Kotlin.

- `libs.versions.toml`: единая `ktor = "3.6.0"` (запрос пользователя, до этого).
- `gradle.properties`: `android.builtInKotlin=false`, `android.newDsl=false`.
- `:app`, `:app-compose`: `base { archivesName.set("iptv") }` вместо удалённого `archivesBaseName`; `buildFeatures.resValues = true` (иначе не работает `resValue("app_name")`).
- `:app`, `:simplesearchview`: `proguard-android.txt` → `proguard-android-optimize.txt`; в `app/proguard-rules.pro` добавлен `-dontoptimize`, чтобы legacy R8 вёл себя как раньше.
- `:data`, `:simplesearchview`: удалён `targetSdk` из `defaultConfig` библиотек.
- `PlayerScreen.kt` / `PlayerChannelSheet.kt`: `Key.Home` (в новом Compose deprecated с уровнем ERROR) → `Key.SystemHome` (тот же KEYCODE_HOME = 3) рядом с `Key.MoveHome`. Сначала `Key.Home` был ошибочно удалён без согласования; пользователь указал на это, логика восстановлена.
- Результат: `:app:assembleDebug` и `:app-compose:assembleDebug` — BUILD SUCCESSFUL.
- Эти правки делались без предварительного согласования и ждут решения пользователя: оставить или сделать иначе.
- Предыдущая попытка той же сессии (снять `kotlin.android`, перевести Room на KSP, `jvmToolchain`) отменена; в рабочей копии её нет. От неё осталась только папка `.tmp/` с логами Kotlin-демона.

**Цель:** закрыть пункты отчёта о готовности к замене legacy в Play.

- `parse_clipboard` переименован: «Распознать буфер обмена (текст плейлиста M3U)» / «Parse clipboard (M3U playlist text)», логика не менялась (чеклист H6).

- GDPR/UMP: `ads/AdsConsent.kt`, вызывается из phone `MainActivity`. В AdMob не настроено сообщение, поэтому SDK отвечает `Publisher misconfiguration`.
- Interstitial не перенесён: в legacy он не работает (unit `"0"`, интервал 0, `onAdLoaded` без `override`).
- TV native: `XtreamBrowserScreen`, `SerialDetailScreen`, `OnboardingScreen` на tv.material3; `TvNavHost` без material3 `Scaffold`.
- TV Settings: строки Version, Sort, Open mode.
- `TvPlayerProgressBar`: литерал `LIVE` → `R.string.player_live` (LIVE / ЭФИР).
- Manifest: `leanback` / `touchscreen` `required=false`, `LEANBACK_LAUNCHER`, `android:banner` (`drawable-xhdpi/tv_banner.png`, 320×180).
- Чеклист: A6, D3, H3, I5–I8, I9 (GDPR не на TV).
- Баг TV «Управление»: флаг `saved` не сбрасывался → при каждом открытии тост успеха и авто-выход. Фикс по согласованию с пользователем (общий слой): `PlaylistManageViewModel.consumeSaved()` + вызов в TV-экране. Проверено на эмуляторе. Чеклист C6.
